## Candidate graph requirements

If GAIA builds an EarthGraph or ecosystem knowledge graph, represent geography, temporal validity, source lineage, observation/model distinction, and uncertainty explicitly. A node or relationship should not be treated as true merely because it is stored in the graph.

Candidate claim metadata includes source/version, observation time and valid-time interval where relevant, spatial scope/resolution, method, confidence/uncertainty, provenance type, contradictory evidence, correction/supersession links, and downstream dependent artifacts.

Distinguish ecological observations from inferred habitat boundaries, predicted species presence, modeled carbon estimates, and proposed interventions. Preserve multiple conflicting sources where unresolved; avoid counting derivative copies as independent corroboration. Track when source data are withdrawn or superseded so downstream maps, summaries, and decisions can be reviewed.

Any schema must be reconciled with GAIA-Ontology and approved Core contracts before implementation. Apply privacy, sensitive-location protection, licensing, retention, and deletion requirements. This proposal does not assert an EarthGraph currently exists.
